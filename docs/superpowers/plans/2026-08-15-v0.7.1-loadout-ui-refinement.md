# OWCA v0.7.1 Loadout UI Refinement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the technical inventory form inside Create Character with a clear prepare, add, and finalize workflow while preserving the full standalone Manage Loadout editor.

**Architecture:** `CharacterState`, `CharacterInventoryService`, and the v4 save contract remain authoritative and unchanged. `CharacterInventoryEditor` gains explicit creation and maintenance presentation modes; both modes call the same service, while `CharacterCreator` alone handles the transition to Review. `CharacterInventoryCalculator` changes only the projection rule for valid definitions whose source omits weight.

**Tech Stack:** Godot 4.7, typed GDScript, existing headless SceneTree tests, JSON-backed equipment definitions, Windows renderer verification for the printable dossier.

## Global Constraints

- Keep PR #13 in draft until automated tests, manual UI inspection, and printable dossier verification pass.
- Keep the application version at `0.7.1-dev`; do not begin v0.8 weapon modifications.
- Preserve character state/envelope version 4 and interoperability schema `1.3.0`.
- Do not add custody, provenance, audit, durable-ID, or reconciliation controls to creation mode.
- Keep all existing maintenance controls available in Manage Loadout.
- Treat a valid catalogue definition without `weight_kg` as `0 kg`; a missing definition remains unresolved and blocks finalization.
- Preserve usability at the 960x650 minimum window with no horizontally hidden primary action.
- Do not modify or stage the user's local Godot AI plugin or export settings from the normal project checkout.

---

## File map

- `OWCA/scripts/character_inventory_calculator.gd`: derives resolved items, carried weight, armour, and unresolved-definition warnings.
- `OWCA/ui/character_inventory_editor.gd`: owns both inventory presentation modes and delegates every mutation to `CharacterInventoryService`.
- `OWCA/ui/character_creator.gd`: selects creation mode, translates loadout state into player-facing labels, and moves successful finalization to Review.
- `OWCA/ui/loadout_manager.gd`: selects maintenance mode explicitly; its behavior otherwise remains unchanged.
- `OWCA/tests/character_inventory_calculator_test.gd`: proves the revised omitted-weight rule and missing-definition boundary.
- `OWCA/tests/inventory_ui_test.gd`: proves creation-mode simplicity, maintenance-mode completeness, defaults, restore behavior, finalization, and minimum-width fit.
- `OWCA/CHANGELOG.md`, `OWCA/ROADMAP.md`, `README.md`: replace planned language with verified v0.7.1 behavior after implementation.
