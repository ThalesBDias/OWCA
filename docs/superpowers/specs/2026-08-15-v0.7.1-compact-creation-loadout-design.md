# OWCA v0.7.1 compact creation loadout design

## Purpose

The Loadout stage inside Create Character should support character creation, not equipment inspection. It must make starting and optional equipment quick to scan and easy to add without presenting weapon profiles, source references, availability, weight, armour values, or other catalogue details for each item.

This is a presentation-only refinement of the existing `0.7.1-dev` workflow. It does not introduce a new save version or change inventory calculations.

## Scope

Only the Loadout stage embedded in Create Character changes.

The following remain unchanged:

- the standalone Manage Loadout workflow;
- the Armoury catalogue;
- inventory records, catalogue definitions, and JSON compatibility;
- carried-weight, encumbrance, and armour calculations;
- loadout finalization and starting-grant reconciliation;
- character dossiers and equipment data available for future tooltips or popups.

## Creation presentation

### Owned equipment

Starting and optional equipment remain grouped as Weapons, Armour, Ammunition, and Gear. Each entry displays only its resolved name and a quantity when the quantity is greater than one:

- `Lasgun`
- `4x Charge Pack`
- `2x Frag Grenade`

Single-item weapons and armour do not display a redundant `1x` prefix. Optional additions retain their Remove button. Starting equipment remains protected from direct removal during creation.

The creation list does not display item profiles, craftsmanship, origin, custody, location, source, availability, weight, armour points, or labels such as `STARTING EQUIPMENT` and `OPTIONAL ADDITION` on every row. The surrounding section already communicates whether an item is starting or optional equipment.

### Adding optional equipment

Create Character retains:

- equipment search;
- category filtering;
- an item selector;
- the **Add Equipment** button.

Selector entries display item names only. The selected-item detail panel is omitted in creation mode because it does not affect the act of adding the item. Selecting and adding an item still uses the complete catalogue definition internally.

The maintenance editor continues to show category labels, profiles, source information, availability, weight, and its existing detailed controls.

## Data and behavior

No authoritative state or calculated field changes. Adding equipment continues to create the same durable owned-item record with the existing creation defaults:

- character custody;
- Common craftsmanship;
- carried location;
- later-issue origin.

All hidden catalogue data remains available to calculations, persistence, dossiers, Manage Loadout, Armoury, and future detail affordances.

## Responsive behavior

The compact rows must fit without horizontal scrolling at the supported 960x650 minimum window. Long names use the existing wrapping behavior. Removing the detail panel should shorten the stage and reduce vertical scanning.

## Verification

Regression coverage must prove that:

- creation starting and optional rows show names and only meaningful quantities;
- creation rows do not show weapon profiles or repeated per-item origin labels;
- the creation selector contains names without category suffixes;
- the selected-item detail panel is absent in creation mode;
- Search, category filtering, Add Equipment, and optional-item removal remain functional;
- Manage Loadout retains its full catalogue detail panel and maintenance controls;
- the creation stage remains usable at 960x650;
- the complete automated suite remains green.

The application remains `0.7.1-dev`, and the unreleased changelog records this refinement without claiming a new release.
